# MVM バイトコード・実行系リファレンス

## 0. 概要

MVM（Myon Virtual Machine）は、Myon の AST をバイトコードに変換して実行する
スタック型 VM です。この文書は現在のコンパイラ・VM・シリアライザーを説明します。
言語の構文と標準ライブラリは [言語リファレンス](myon_spec.md) を参照してください。

| 構成 | 実装 |
|---|---|
| 命令番号と定数タグ | `src/mvm_bytecode.h` |
| Module / Chunk、読み書き、逆アセンブル | `src/mvm_chunk.h`、`src/mvm_chunk.c` |
| AST からのコンパイル | `src/mvm_compiler.c` |
| 実行・フレーム・タスク | `src/mvm_vm.c` |
| 標準ライブラリへの接続 | `src/interpreter.h`、`src/interpreter.c` の myon_bridge_* |

### 0.1 文書の範囲

ここでいう `.myc` は MYC1 形式のファイルです。現在の書き込みバージョンは1.2です。
この番号は言語や配布バイナリのバージョンとは別です。命令番号・フィールドの読み書きは
上記ヘッダとシリアライザーを照合してください。

本文の節番号はこの文書を指し、「言語仕様」は myon_spec.md を指します。
過去の Step / Phase の実装計画は、この文書の動作要件として扱いません。

### 0.2 実行経路

`.myon` の通常実行はツリーウォーク、`.myc` は MVM です。
MVM は変数のスロットをコンパイル時に解決し、実行時に命令列を読み進めます。
標準ライブラリと Value の実装はツリーウォーク側と共有します。
性能差はプログラムと実行環境で変わるため、特定の高速化率を規定しません。

## 1. Module と Chunk

### 1.1 スタックマシン

式の評価結果を Value のオペランドスタックに積み、演算命令が入力を取り出して結果を積みます。
例えば `1 + 2` は定数2つのロードと ADD で表現できます。

```text
PUSH_CONST index_of_1
PUSH_CONST index_of_2
ADD
```

### 1.2 命令の符号化

先頭1バイトがオペコードで、後続のオペランドは命令ごとに決まります。
多バイトのオペランドはリトルエンディアンです。パディングはありません。

| 表記 | 幅 | 用途 |
|---|---|---|
| u8 | 1バイト | 引数・戻り値・捕捉の個数 |
| u16 | 2バイト | 定数・スロット・チャンク・ネイティブ名の索引 |
| s16 | 2バイト | ジャンプの相対距離 |

MAKE_CLOSURE は捕捉数に応じて長さが変わります。命令を走査する処理は
`mvm_instruction_len()` を使用し、この例外も扱う必要があります。

### 1.3 定数プール

定数プールはチャンクごとではなく、Module 全体で共有します。
int / float / str / bool / nil / TypeSpec を保存し、命令は u16 索引で参照します。
通常の bool と nil の生成には専用命令を使います。
配列・Map・構造体のインスタンスは実行時に作り、定数プールには保存しません。

値の定数は追加時に重複を検査します。TypeSpec は複製して登録し、同じ方法での重複排除はしません。

### 1.4 チャンク

トップレベル、関数、ラムダ、構造体メソッドをそれぞれチャンクへコンパイルします。
チャンクは次の情報を持ちます。

| 情報 | 用途 |
|---|---|
| name | 診断用の名前。トップレベルは `<main>`、メソッドは `Struct.method` |
| num_params / num_locals / ret_count | 引数・ローカルスロット・戻り値の情報 |
| is_async | async 関数かどうか |
| captured | 捕捉対象ローカルを示すビットマップ |
| code | バイトコード |
| lines | 命令位置とソース行の対応 |

Module はこれらのチャンク、共有定数プール、ネイティブ名一覧、entry_chunk、Source Info を所有します。

## 2. 値と所有権

MVM は `src/value.h` の Value / Obj を使用します。
int / float / bool は Value 内に保持し、文字列・配列・Map・struct・関数・Task は Obj を参照します。

### 2.1 コピーと解放

`value_copy()` は所有する参照を追加し、`value_free()` は参照を解放します。
定数をロードするときも、定数プールの値を借用したままスタックに置くのではなくコピーします。
命令が取り出した値は、結果へ所有権を移すか、その命令で解放します。

### 2.2 循環回収

Obj と UpvalueCell は参照カウントに加えて循環回収の対象です。
外部ルートから到達できない循環を割当量に応じて回収し、インタプリタ破棄時にも検査します。
未完了 async のコンテキスト・VM スタック・捕捉セルはループ破棄時に解放します。
管理対象外の C リソースや FFI ライブラリの所有物は、このコレクタの対象ではありません。

### 2.3 スタック上の値

各オペランドスロットは Value を1つ保持します。複合値のコピーは Obj の共有になります。
破壊的な配列・Map 操作は、同じ Obj を参照する値からも観測されます。

### 2.4 nil と void

PUSH_NIL は TYPE_NIL を積みます。通常の単一変数への nil 代入は CHECK_NOT_NIL で検査します。
RET 0 の呼び出し結果は、式文の POP が別の値を消費しないよう、VM 内では nil 1個へ正規化します。
これは内部の呼び出し規約で、利用者が nil を一般の変数へ代入できるという規則ではありません。

## 3. スタックとフレーム

### 3.1 実行状態

VM は Value のオペランドスタックと呼び出しフレームの配列を持ちます。
async タスクはそれぞれの VM 状態とエラー復帰先を保持し、Module、グローバル変数、標準ライブラリの
ブリッジを VMShared 経由で共有します。

### 3.2 Frame

| メンバー | 役割 |
|---|---|
| chunk / ip | 実行中のチャンクと次の命令位置 |
| base | ローカルスロット0のスタック位置 |
| fn_slot | 呼び出した関数値の位置。メソッド等では -1 |
| upvalues | 呼び出したクロージャから借用する捕捉セル |
| cells | このフレームが所有する捕捉ローカルのセル |
| globals_frame | main のスロットを共有グローバル領域へ接続する印 |

Frame 自体が期待戻り値数のフィールドを持つわけではありません。RET のオペランドと
コンパイルされた代入処理が値数を扱います。

### 3.3 ローカルとグローバル

関数入口で num_locals 分のスロットを確保し、先頭 num_params 個を引数として使います。
メソッドでは self がスロット0、その後ろが宣言引数です。
捕捉されたローカルは UpvalueCell が値を所有します。

トップレベル変数は VMShared のグローバル配列に置きます。main 内のローカル命令と、
別関数内の LOAD_GLOBAL / STORE_GLOBAL が同じ領域を参照します。

### 3.4 上限

`MVM_MAX_FRAMES` は1024フレーム、`MVM_STACK_MAX` は実装ヘッダ付近の定義を参照してください。
VM は上限超過を実行時エラーとして報告します。ネイティブ側の再帰呼び出しには
インタプリタのメインスタック/コルーチン用の別の予算が適用されます。

## 4. 命令

スタック効果は下から上の順に `[入力 → 出力]` と記します。
表には `MOP_` を省いたニーモニックを使います。番号は `mvm_bytecode.h` の enum が定義します。

### 4.0 番号帯

| 番号帯 | 分類 |
|---|---|
| 00–0F | 定数・スタック |
| 10–2F | 算術・比較・単項 |
| 30–3F | ローカル・グローバル |
| 40–4F | 分岐 |
| 50–5F | 関数・捕捉・async |
| 60–6F | コレクション |
| 70–7F | 構造体 |
| 80–8F | 文字列・キャスト |
| 90–9F | ネイティブ呼び出し |
| A0–AF | 複数代入・nil検査 |

### 4.1 定数とスタック

| 命令 | オペランド | スタック効果 |
|---|---|---|
| NOP | なし | `[ → ]` |
| PUSH_CONST | u16 idx | `[ → copy(constants[idx])]` |
| PUSH_TRUE / PUSH_FALSE / PUSH_NIL | なし | `[ → value]` |
| POP | なし | `[v → ]` |
| DUP | なし | `[v → v copy(v)]` |

### 4.2 算術

ADD / SUB / MUL / DIV は `[a b → result]` です。型・オーバーフロー・ゼロ除算は
共有ランタイムの規則を使います。ADD は str 同士の連結にも使います。
異なる型の算術演算を自動で浮動小数点へ昇格させる命令ではありません。

### 4.3 比較

EQ / NEQ / LT / GT / LE / GE は `[a b → bool]` です。
言語の二項演算は `myon_bridge_binary()` を通ります。
int 同士は long long のまま比較します。`value_equal()` によるコンテナ検索と、
言語の `==` の対応範囲を同一視しないでください。

### 4.4 単項

NEG は `[v → -v]`、NOT は `[v → !v]` です。
NEG は最小 int の符号反転をオーバーフローとして拒否します。
NOT は共有ランタイムで bool を要求します。

### 4.5 短絡評価

and/or の専用二項命令はありません。条件ジャンプで、結果が決まる場合の右辺評価を省略します。
条件ジャンプが取り出した値の判定には VM の `value_truthy()` を使用します。

### 4.6 スロット

| 命令 | オペランド | 効果 |
|---|---|---|
| LOAD_LOCAL / LOAD_GLOBAL | u16 slot | 対象スロットをコピーして積む |
| STORE_LOCAL / STORE_GLOBAL | u16 slot | top を取り出してスロットへ移す |
| LOAD_UPVALUE / STORE_UPVALUE | u16 idx | 捕捉セルを読む/更新する |

格納先の既存値は解放します。ローカル・捕捉セル・グローバルの区別は名前解決で決まります。

### 4.7 分岐

JUMP / JUMP_IF_FALSE / JUMP_IF_TRUE は s16 off を持ちます。
距離の基準はオペランド直後のアドレスです。条件ジャンプは条件を pop します。
コンパイラは未確定の前方距離を後で埋め、ループには後方ジャンプを生成します。
if/elif/else、while、range、配列反復、break/continue はこの命令群に展開します。

### 4.8 関数値と捕捉

MAKE_CLOSURE のオペランドは次の可変長形式です。

```text
u16 chunk_idx
u8 nupval
nupval × (u8 kind, u16 index)
```

kind 0 は呼び出し側のローカルセル、kind 1 は呼び出し側の upvalue を参照します。
結果として関数値を1つ積みます。捕捉なしの関数でも nupval のバイトを持ちます。
チャンクの is_async は、生成する関数値にも反映されます。

### 4.9 呼び出しと戻り値

CALL argc は u8 の引数数を取り、`[fn args... → returns...]` として呼び出します。
async 関数では本体をその場で実行せず、Task 値を積みます。
SPAWN_ASYNC argc も関数値と引数からタスクを生成します。
AWAIT は `[task_or_value → result]` で、通常の値ならその値を返します。

RET n は u8 の戻り値数を持ちます。結果を退避してフレームの値とセルを解放し、
呼び出し側へ戻します。ユーザー関数の複数 ret は複数の値を積みます。
ネイティブの `(value, error)` 等は型情報なしの配列で渡されるため、
必要な代入箇所で UNPACK を使います。

### 4.10 配列・Map

| 命令 | オペランド | スタック効果 |
|---|---|---|
| NEW_ARRAY / NEW_MAP | u16 type_idx | `[ → container]` |
| ARRAY_PUSH | なし | `[arr value → arr]` |
| INDEX_GET | なし | `[container key → value]` |
| INDEX_SET | なし | `[container key value → ]` |

型索引は TypeSpec の定数です。ARRAY_PUSH は VM に実装されていますが、
現言語の配列リテラル構文を示すものではありません。配列添字は型と範囲を検査します。

### 4.11 構造体

| 命令 | オペランド | スタック効果 |
|---|---|---|
| NEW_STRUCT | u16 name_idx | `[fields... → struct]` |
| GET_FIELD | u16 name_idx | `[struct → value]` |
| SET_FIELD | u16 name_idx | `[struct value → ]` |
| INVOKE | u16 name_idx, u8 argc | `[receiver args... → returns...]` |

name_idx は文字列定数を指します。構造体のフィールド数・継承・メソッド探索には
宣言 AST を参照します。INVOKE はレシーバの宣言と親宣言から対応するメソッドチャンクを探します。
構造体以外の組み込みメソッドはブリッジ経由で呼びます。保存済み `.myc` の制約は7節にあります。

### 4.12 文字列

TO_STR / CAST_STR は `[v → str]`、STR_CONCAT は `[a b → concatenated]` です。
補間を含むリテラルは、定数断片・部分式・文字列化・連結にコンパイルします。
エスケープはコンパイル時にリテラル断片へ適用し、変換後の文字列を定数として保存します。
補間された値には再適用しません。

### 4.13 変換と検査

| 命令 | オペランド | 効果 |
|---|---|---|
| CAST_INT / CAST_CHAR | なし | top を共有ランタイムの変換規則で変換 |
| MAKE_ERROR | なし | str から error を生成 |
| UNPACK | u8 n | 型情報なしの配列1つから n 個の値を積む。個数不一致はエラー |
| CHECK_NOT_NIL | なし | top を消費せず、nil なら通常変数への代入を拒否 |

int への変換は文字列の範囲、float の有限性と int64 範囲を検査します。
char の実装上の文字幅については言語リファレンス2節を参照してください。

### 4.14 ネイティブ呼び出しと module

CALL_NATIVE は u16 native_id と u8 argc を持ちます。
native_id は Module のネイティブ名一覧の索引です。VM は名前をブリッジへ渡し、
共有する標準ライブラリを呼び出します。戻り値は Value 1つで、複数値はタプル配列に入ります。

組み込みmodule宣言はmainの先頭で有効化するネイティブ呼び出しになります。
標準ライブラリ呼び出しと明示的な配列/Map生成の前にはmoduleの検査を挿入し、
ブリッジも有効な宣言を確認します。検査は利用者の引数を評価する前です。
内部のmodule命令に使う名前はソースからの呼び出しを拒否します。
宣言と検査は保存済み `.myc` にも含まれます。
外部ファイル・パッケージの取り込みはコンパイル時に未対応として拒否します。

### 4.15 命令の確認

実際の命令列は `--dump-bytecode` で確認できます。命令番号を列挙するソースは
`src/mvm_bytecode.h`、固定オペランド幅と可変長の扱いは `mvm_opcode_operand_bytes()` と
`mvm_instruction_len()` です。命令の追加時はコンパイラ・VM・読み書き・逆アセンブルを照合します。

## 5. 静的スコープ解決

コンパイラは関数ごとにローカル名・深さ・スロット、捕捉記述子を管理します。
名前をローカル・upvalue・グローバル・ネイティブに分類し、対応する命令を生成します。
未解決の名前はコンパイルエラーになります。

明示ブロックのシャドーイング、関数内からの外側更新、メソッドの境界は
言語リファレンス9節の規則を適用します。実装経路によってエラー段階に差が残るため、
コンパイルエラーと実行時エラーの一致までを保証する規則ではありません。

ブロック退出時はコンパイラの名前の可視性を変更します。ローカル領域はフレーム入口で
確保済みなので、ブロック終了のたびにその領域を POP して縮める方式ではありません。
`myon.expose` は束縛の有効な深さを外側へ移します。
num_locals は割り当てたスロットの最大使用数から決めます。

## 6. MYC1 ファイル形式

多バイト整数と double のビット列はリトルエンディアンです。
以下の `string` は `u32 length` とその長さのバイト列で、NUL 終端は保存しません。

### 6.1 配置

```text
Header (32 bytes)
Source Info
Constant Pool
Native Table
Chunk Table (metadata, code, line entries for each chunk)
```

### 6.2 ヘッダ

| オフセット | 幅 | 内容 |
|---|---|---|
| 0 | 4 | MYC1 (`4D 59 43 31`) |
| 4 | 1 | major = 1 |
| 5 | 1 | minor = 2 |
| 6 | 1 | endian = 1 (little) |
| 7 | 1 | flags = 0 |
| 8 | 4 | 定数プールのオフセット |
| 12 | 4 | 定数プールのバイト長 |
| 16 | 4 | チャンク表のオフセット |
| 20 | 4 | チャンク数 |
| 24 | 4 | entry_chunk |
| 28 | 4 | Source Info のオフセット |

moduleの有効化・検査を含む実行契約のため、現在はmajor/minorの完全一致を要求します。
1.1以前や未来のminor形式は読み込まず、元ソースから1.2へ再コンパイルします。
ローダーのバージョン・オフセット等の検査は `mvm_module_read_file()` にあります。

### 6.3 定数プール

先頭に u32 count、その後に count 個の `[u8 tag, payload]` を置きます。

| タグ | 内容 |
|---|---|
| 01 | int: s64 |
| 02 | float: IEEE 754 double の8バイト |
| 03 | str: string |
| 04 | bool: u8 (0/1) |
| 05 | nil: payload なし |
| 10 | TypeSpec: 下記の再帰形式 |

#### 6.3.1 TypeSpec

順序は base(u8)、必要な追加情報、arg_count(u16)、型引数です。

1. base が STRUCT / TYPEPARAM なら name(string)。
2. ARRAY / MAP なら elem(TypeSpec)。
3. MAP なら key(TypeSpec)。
4. すべての base で arg_count(u16) を書き、その数の TypeSpec を続ける。

プリミティブでも arg_count を省略しません。NULL の型は UNKNOWN と arg_count=0 で保存します。
base の数値は `src/types.h` の Type enum を使います。

### 6.4 チャンク表

先頭の u32 count の後に、各チャンクを次の順で置きます。

```text
name          string
num_params    u16
num_locals    u16
ret_count     u16
is_async      u8
captured_len  u16
captured      captured_len bytes
code_len      u32
code          code_len bytes
line_count    u32
lines         line_count × (u32 code_off, u32 line)
```

コード内の定数索引は Module 全体のプール、チャンク索引はこの表を指します。
宣言 AST 自体はこの形式に含みません。

### 6.5 Source Info と stale 検査

Source Info は mtime(s64)、size(u64)、hash(32 bytes)、path(string) の順です。
hash の先頭8バイトはソースの FNV-1a 64bit で、残り24バイトを0にします。
SHA-256 の署名・真正性検査ではありません。

`.myc` 実行時に、記録されたパスまたは対応する `.myon` の情報と照合します。
不一致は既定で警告し、`--strict-stale` では終了コード65で中止します。
元ソースがなければ検査を省略します。検査は `src/main.c` の `check_myc_stale()` にあります。

### 6.6 ネイティブ名一覧

u16 count に続けて count 個の string を保存します。
CALL_NATIVE の索引はこの名前一覧を参照するため、実行バイナリ内の C 関数ポインタを
ファイルへ直接保存することはありません。

## 7. 対応範囲と制約

算術・比較・制御構文・関数・複数戻り値・配列/Map・文字列補間・キャストを扱います。
クロージャは boxed upvalue、ジェネリクスは型消去、async は共有イベントループを使用します。
net/http/ffi のネイティブ API はブリッジ経由で呼び出します。

| 制約 | 報告される段階 |
|---|---|
| external.* の module 取り込み | コンパイル時 |
| パッケージの module 取り込み | コンパイル時 |
| MVM REPL | 未実装 |
| 構造体宣言 AST が必要な処理を保存済み `.myc` だけで実行 | 宣言情報がないため実行に制約 |

`--run-mvm` はソースの Program を保持しますが、`.myc` には構造体宣言 AST を保存しません。
したがって、同じソースの `--run-mvm` が成功しても、構造体を使う保存済み `.myc` の
単体実行が同じ条件で成功するとは限りません。

### 7.1 async とネイティブ

async 関数は呼び出し時に Task を生成します。await は完了を待って結果を受け取ります。
I/O とタイマーはイベントループへ制御を返します。ソケットや FFI の状態はブリッジに保持します。

### 7.2 コールバック境界

VM の関数値と、ツリーウォークの FuncDecl / Env を参照する関数値は、同じ実行表現ではありません。
ブリッジに登録した VM 呼び出し口で関数値を識別し、配列の map/filter/reduce と FFI
コールバックからバイトコードを実行します。呼び出しごとにオペランド・フレームのスタックを
作り、グローバル変数・捕捉セル・標準ライブラリの状態は呼び出し元と共有します。
この経路は保存済み `.myc` でも利用でき、ソース AST は不要です。

VM とネイティブの相互再帰には C スタックに応じた深さ制限を適用します。
コールバック用スタックはエラーやタスク終了でも解放します。FFI コールバック内の
実行時エラーは外部 C フレームを越えて伝播させず、診断を表示して0を返します。

### 7.3 捕捉セル

捕捉されたローカルはフレーム作成時に UpvalueCell へ移します。
定義側とクロージャは同じセルを共有し、読み書きが双方から見えます。
フレーム終了時はフレームの参照を、関数値破棄時は捕捉セルへの参照を解放します。

### 7.4 ジェネリクス

型引数ごとの専用チャンクを生成する単相化は行いません。
コンパイラは型引数を消去して命令を生成します。TypeSpec の保存情報と、
実行時にすべての型制約が検査されることは区別してください。

## 8. エラー

VM の診断は `myon: runtime error at line N:` を使います。
命令位置から行表を引き、ソースが参照できる場合は抜粋を表示します。
行情報がない場合の番号は0です。ネイティブの `(value, error)` 返却と、
VM を中止する実行時エラーは別の経路です。

無効なヘッダや読み込み失敗はロードエラーになります。ローダーでの検査は、
任意の外部バイトコードを隔離して実行するサンドボックスを構成するものではありません。
エンジン間の診断本文・エラー段階の差は [既知の問題](../known-issues.md) を参照してください。

## 9. CLI

| 操作 | コマンド |
|---|---|
| ソース実行 | `./myon program.myon` |
| バイトコード出力 | `./myon --compile program.myon -o program.myc` |
| 保存済みバイトコード実行 | `./myon program.myc` |
| メモリ上でコンパイルして実行 | `./myon --run-mvm program.myon` |
| 逆アセンブル | `./myon --dump-bytecode program.myc` |
| ソースの字句解析表示 | `./myon --tokens program.myon` |

ファイル引数の先頭が MYC1、または拡張子が `.myc` なら MVM へ渡します。
標準入力を表す `-` はソースです。`--compile` の出力省略時は拡張子を `.myc` へ置き換えます。
`--run` というフラグはありません。`--strict-stale` の挙動は6.5節を参照してください。

## 10. 未実装の機能と検討項目

外部 module のリンクと MVM の REPL は未実装です。
値表現の変更、レジスタ方式、命令融合、単相化は実装済みの仕様ではありません。
将来の変更を前提に `.myc` を生成しないでください。

## 11. 検証

`tests/mvm_compiler_tests.sh` はコンパイルと逆アセンブル・保存/読込を検査します。
`tests/run_mvm_tests.sh` はソースをツリーウォークと `--run-mvm` で各1回実行します。
後者は保存済み `.myc` の全機能の単体実行を検査するものではありません。

出力ケースは両者の正常終了と出力一致、エラーケースは終了コード1/65の一致を確認します。
既知の段階差は `tests/cases/<name>.mvm-exit` に `ツリーウォーク MVM` の順で期待コードを
記録します。現在の3件は `step8_shadow`、`step9_collision`、
`p51_scope_multi_assign_shadow_forbidden` で、いずれも `1 65` です。
この指定がない段階差や、指定と異なる終了コードは失敗になります。
未対応診断を持つケースは除外として記録します。診断本文の一致は要求しません。
`runtime_regressions.sh`、`numeric_regressions.sh`、`diagnostic_regressions.sh` には、
終了コードや特定の診断をより限定した検査があります。
